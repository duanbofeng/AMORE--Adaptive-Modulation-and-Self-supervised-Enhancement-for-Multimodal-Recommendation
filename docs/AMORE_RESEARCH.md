# AMORE 重构与实验依据

本次交付是可验证的研究候选集合。默认 AMORE 为精简对照，亲和力、额外对比损失、图重加权和初始化增强均默认关闭。尚未运行正式数据集，不能据此宣称提升、最优模块组合或论文创新已成立。

## 1 代码与论文审计

审计对象为本地 `papers/AMORE.docx`、`papers/GUME.pdf`、`papers/MGCN.pdf`、`papers/IIMRec.pdf`、`papers/SG-URInit.pdf`，以及 `src` 和 `old_model/src/models/gume.py`。`old_model/src/models/amore.py` 只有继承入口，旧 AMORE 实际实现位于同目录的 `gume.py`；`main.py` 是启动入口。

| 发现 | 影响 | 本次处理 |
|---|---|---|
| 旧 AMORE 对每个用户的边分数做 softmax 后使用统一阈值 | 均匀分数为 1/用户度数；不同用户的阈值含义不一致，分数也不是可靠性概率 | 新候选不使用该硬阈值，提供局部、物品、全局和打乱对照 |
| 边调制结果平均回同一物品再传播 | 不同用户看到同一物品表示，论文中的用户相关边消息和实现不一致 | 局部权重保留在语义 user-item 聚合矩阵上 |
| `fine_grained_image/text` 计算残差增强，但最终使用 `*_base` | `residual_alpha` 不影响最后融合 | 不复用这条路径；旧实验不能据此支持残差增强有效 |
| 旧稿描述 adaptive BPR，而配置 `use_adaptive_bpr: False` | 方法声明和实际运行不一致 | 默认标准 BPR，训练预测使用同一内积函数 |
| `quick_start` 按 test 指标挑选最优超参数 | 测试集参与选择，使结论偏乐观 | 改为 validation 选择；整个网格只对选中配置测一次 test |
| trainer 每轮测 test，却没有保存实际最优模型 | 易反复观察测试集，无法可靠导出最佳模型 | 保存并恢复 validation 最优 checkpoint，最后评估 test |
| GUME 数据集参数全部注释 | 默认运行缺少 `n_layers` 等 | 根据原注释恢复各数据集默认值；不是重新调参结果 |
| `find_inter` 每 10 条边分组，`inter.json` 不区分 k | 非 10 的 k 和旧缓存可能造成错误图 | 基于实际稀疏行索引计算交集，忽略旧图缓存 |
| 全量 item-item cosine 矩阵 | O(I²) 峰值相似度存储 | 分块精确 KNN；计算量仍为 O(I²)，不是近似检索 |
| `np.float` 与声明的 NumPy 版本不兼容；评估先四舍五入 | 运行失败或掩盖细微差别 | 修复类型；保留未舍入指标 |

论文中“亲和力等于拓扑置信度”“均值方差对齐消除语义差异”等表达目前缺少直接证据。相似度只能作为偏好一致性的代理，不能证明某个真实点击是噪声。即使完整模型涨点，也不能自动支持每个机制解释。

## 2 保留的基线与精简路线

`gume` 保留原始 GUME 的编码、粗细融合、BM/UM/VT 损失及默认参数，统一采用修正后的评估协议。工程修正包括稳定的 cross entropy 形式 InfoNCE、图缓存、分块 KNN、交集构造和推理嵌入缓存。KNN 对负相似度截为 0，零权重边不入图；原实现保留负值，因此这属于明确的图稳定化差异。k=10、非负相似度且不存在错误旧缓存时，构图目标与原实现一致，但不能称逐位复现论文成绩。

`gume_no_um` 同时移除 UM 与其专属正则 `reg_weight_2`，因此能实际移除两套额外用户参数及扩展模态传播。它是整条分支的消融；若要只去掉 UM 损失而保留专属正则，可手动 `--set um_loss=0`。`gume_coarse`/`gume_mean` 会移除不用的融合网络。`gume_lean` 是多项删减后的台阶对照，不能把它与完整 GUME 的差值归因于某一模块。

AMORE 的默认结构：

1. 仅训练一套用户 ID 嵌入和一套物品 ID 嵌入。
2. 在原始训练 UI 图上做 LightGCN，包含第 0 层后取均值，得到 C。
3. 每个模态有一个线性投影，`Q_m = E_item ⊙ sigmoid(W_m F_m + b_m)`；这沿用 GUME/MGCN 的行为引导特征净化思想。
4. 对 Q_m 做独立 KNN 图传播，再以原训练图的对称度归一化聚合到用户，得到 S_m。
5. `E = C + α mean_m(S_m)`，默认 α=1/3；使用内积评分。
6. 默认损失 `L = mean softplus(s_neg - s_pos) + λ/(2B) (||E_u^0||² + ||E_pos^0||² + ||E_neg^0||²)`。L2 只作用于批内 ID 嵌入，不应写成全部参数正则。

默认没有额外用户模态表、粗细分离 MLP、Gaussian alignment、UM 噪声分支或自定义维度 BPR。原始高维特征冻结以降低优化器开销。仍需存储原始特征和稀疏图；冻结不会让这些存储消失。`amore_train_features` 可检验冻结是否损害效果。

GUME lean 与 AMORE base 并非单因素差异：AMORE 把 sigmoid 前的两次仿射映射合成一层、去掉 KNN 自环、默认单层 II 传播，并对初始 ID 嵌入而非最终融合嵌入施加 L2。GUME baby 默认 II 深度为 2。两者的直接对比只能作为整体简化效果；严格机制归因应在同一模型内比较，必要时手动对齐图深度和超参数。

`amore_id_only` 在 α=0 且无 CL 时直接运行 ID 路径，不构造语义图和投影参数。其结果可以作为此实现的 LightGCN 风格对照，不能替代经过独立调参的官方 LightGCN 基线。

## 3 亲和力作为待检验假设

对模态 m 的单位归一化原始特征 x_i，使用训练交互历史：

```
h_(u,-i) = sum_{j in N_train(u), j != i} x_j
c_ui = cosine(h_(u,-i), x_i)
r_u = (degree_train(u)-1) / (degree_train(u)-1+gamma)
a_ui = 1 - r_u * (1 - sigmoid(c_ui / T))
w_ui = 1 - beta + beta * a_ui
R_m = D_u^(-1/2) (R_train ⊙ w_m) D_i^(-1/2)
```

单条历史或零范数历史令 r=0，w=1。β∈[0,1]、γ>0、T>0。β=0 必须严格回到无亲和力聚合，这已纳入测试。特征缺失/全零时不把零向量解释为确定偏好。这里的分数是静态的内容一致性代理，不是训练得到的概率、拓扑因果效应或已确认的噪声标签。

权重只控制语义从已交互物品到用户的消息；协同 ID 图不改，候选物品评分不增加逐候选 MLP。语义聚合使用原图度数，不对缩小后的权重再次归一化，以免抵消门控。该设计有意保留“衰减”效应，因此必须同时做全局缩放对照和 `semantic_weight` 调参。

| variant | 含义 | 能回答的问题 |
|---|---|---|
| amore_base | 全 1 | 亲和力是否必要 |
| amore_global | 所有边使用该模态 a 的均值 | 收益是否只是整体语义缩小 |
| amore_item | 先按物品平均 a，再给该物品所有训练边赋同样值 | 局部用户差异是否有用 |
| amore_local | 每条训练边使用自身 a | 保留用户条件信息是否有效 |
| amore_shuffle | 每个用户内部打乱 a | 分数和物品对应关系是否有效 |

预处理在 CPU 上分块计算边分数，避免在 GPU 上产生大规模“边数 × 原始特征维度”张量；每个模态仍需一份用户历史特征和分块中间量。可通过 `diagnostics` 查看均值、标准差、分位数及与用户度数的相关性。只有在同预算下 local 稳定优于 base/global/item/shuffle，才能讨论保留局部亲和力；否则删除或收缩相关主张。

## 4 参考论文的合理借鉴边界

### IIMRec

原文方法见本地 PDF §4.2–4.6；作者资源：[论文](https://arxiv.org/abs/2607.24607)、[代码](https://github.com/Jinfeng-Xu/IIMRec)。它包含空间/频域图、共现图、NCER、UI 扩展、RIG 和邻居 BPR 等多项设计。

本实现仅取可单独验证的部分：

- `graph_mode=shared`：模态 KNN 行归一化后取均值并保留 top-k。
- `cooc_weight>0`：只从 R_trainᵀ R_train 构建分块 top-k 共现图，与语义图加权融合。采用行归一化计数，不是原文 softmax 计数；不加入频域通道。
- `ncer_strength>0`：在保留的候选边上计算共同邻居数/k，将边乘以 `1 + κ c_ij`，再行归一化。不构造全量 B Bᵀ。
- `residual_gate=true`：用 `sigmoid(Linear([C,S]))` 控制语义残差；作用在用户与物品上，且只有一层线性，区别于原文仅物品两层 RIG。门控初始化为 0.5，`amore_half_scale` 提供等初始强度的固定缩放对照。

这些是明确的简化适配，不是 IIMRec 完整复现。暂不加入虚拟 UI 边和伪正样本 BPR，以免同时改变图和监督、增加假正例来源。若实验说明图质量是主因，应把文章重点转向结构验证，不强行保留亲和力故事。

### SG-URInit

原文方法见本地 PDF §3，作者资源：[论文](https://arxiv.org/abs/2604.14839)、[代码](https://github.com/Jinfeng-Xu/SG-URInit)。其核心是按物品逆度数聚合交互物品特征和聚类中心，为模态用户嵌入做一次性初始化。

本实现不新增模态用户表。`history` 用初始净化物品表示的模态均值，按逆物品度聚合后，匹配用户原随机向量范数，并用 `init_blend` 混入共享 ID 用户表。`cluster` 在这个共同空间做一次 KMeans，先混合物品与中心，再进行相同聚合。聚类和初始化均为一次性预处理。

这是针对共享 ID 空间的适配；输入是经过随机 ID 净化的表示，语义可能被削弱，不能照搬“语义保证”的理论表述。需要分别验证 history/cluster、blend、聚类数以及收敛时间。如果初始化获益明显而亲和力无收益，可以形成更小的模型，但初始化本身已有文献来源。

### MGCN 与 EgoGCN

MGCN §2.4 已有模态共享表示与残差的行为感知融合；不能把相同粗细分离重新命名后作为全新贡献。EgoGCN 的边级跨模态融合是现有工作；ACM DOI 页面访问返回 403，本次使用其[作者代码仓库说明](https://github.com/feiyuchen7/EgoGCN)核实方法定位，没有声称逐式复现该文。

## 5 统一实验协议

- 固定原文件的 train/validation/test 划分；拒绝跨 split 重复 user-item 对。
- 图、亲和力、初始化、共现统计仅使用 train 交互。所有物品的预提取内容特征可用于构图，这是传导式推荐协议，不等同于严格归纳冷启动。
- 负采样沿用原框架：从训练出现过的物品采样，排除该用户训练正例；不使用 validation/test 排除负例。
- validation 和 test 均屏蔽原始 train 正例，test 不额外屏蔽 validation，保持仓库原协议。对比文献数字前必须确认其候选集与屏蔽规则一致。
- development 阶段只使用 validation；明确锁定设计与参数后，使用独立的 `--test` 阶段报告结果。不要反复根据 test 输出回头改模型。
- 每个运行选择最佳 validation 轮次并恢复权重；不将不同 seed 挑成“最佳 seed”。正式主表至少 3 个，建议 5 个匹配 seed。
- 推荐主指标 Recall@20，辅助 NDCG@20，完整输出 K=5/10/20/50。主指标在实验前固定。
- 记录完整配置、数据 SHA256、代码 fingerprint、Git 提交及脏状态、软件版本、参数量、预处理时间、纯训练时间、平均 epoch 时间和峰值 CUDA allocated memory。CUDA 数字不是整进程显存或 reserved memory。
- `history.json` 存储验证曲线与平均每批损失，各候选使用同一训练预算。loss_components 的 GUME 为总损失；AMORE 顺序为 BPR、ID L2、加权 CL。
- 数据稀疏实验保留每个用户至少 1 条 train 交互，实际保留比例可能高于请求值；validation/test 不改变，评估仍屏蔽原始 train。抽掉的 train 交互在训练负采样时可能成为负例，这是观测稀疏协议的一部分。
- 特征 zero/shuffle 扰动在训练前施加，并以相同扰动特征重新构图；它测试的是“输入受损后重新训练”，不是训练后突然缺失的零样本鲁棒性。原始数据文件不修改。
- 稀疏用户三分组按原始 train 用户度数阈值；tail 为非零 train 物品度数底部 20% 阈值，cold 为 train 度数 0。分位数有并列时组大小不相等。item-group Recall 仅对该组有 test 正例的用户取宏平均，并报告用户数；没有目标的组不报告。

## 6 分阶段决策

1. core：确认完整 GUME 可运行，比较精简模型和亲和力控制，先跑单 seed 三数据集。它用于排除无效方向，不是最终统计结论。
2. prune：单独移除 GUME 模块；结合精度、参数、耗时做选择，不能只看训练 loss。
3. mechanisms：单独检验共享图、共现、NCER、门控、初始化、CL、单模态。默认双模态优于单模态并非必然。
4. factorial：2×2×2 的亲和力、图增强、history 初始化实验。确认组合是否有互补收益；`factor_000` 与 `amore_base` 同配置，是实现一致性对照。不要将重复对照当作额外 seed。
5. sensitivity：围绕有证据的模块做有限网格。亲和力 β=[0,.25,.5,.75]、γ=[1,5,20]、T=[.1,.2,.5]，先固定其中两项；语义 α=[.1,1/3,.5,1]；CL=[0,.001,.01]；图 k=[5,10,20]；初始化 blend=[0,.25,.5,1]。各模型要匹配搜索预算，GUME 也应调参。
6. robustness：训练保留比例 [.25,.5,.75,1]；图像或文本 zero/shuffle 比例 [.1,.3,.5]；用相同 seed、划分和受损特征比较已选择候选。
7. final：锁定少量候选与超参数，5 seeds，报告均值、样本标准差、匹配 seed 差值和区间，保留不提升的数据集与失败实验。统计显著性不能替代跨数据集效果及机制验证。

不把本集合的 37 个候选默认全组合。`run_suite.py` 默认只生成可检查计划，只有 `--execute` 才启动训练；最终测试需要显式 `--test`。
